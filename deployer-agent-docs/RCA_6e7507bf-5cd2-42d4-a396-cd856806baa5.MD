## 2. Root cause (confirmed, not inferred)
The app's own frontend code contains a fail‑closed release gate that is incompatible with how the Emergent pipeline builds.

- `frontend/craco.config.js:10`: `if (!isDevServer) require("./release-build/verify.cjs").verify();` — runs on every production build (NODE_ENV=production, i.e. `craco build`), skipped only for `craco start` (preview).
- `frontend/release-build/verify.cjs` `verify()` first line reads `backend/release_build.json` (root = `path.resolve(__dirname,'../..')` = `/workspace`). It then also requires `frontend/public/release.json`, requires the two to be byte‑equal, requires a full source‑inventory SHA match, a `lock_sha256` match against `frontend/yarn.lock`, build_context env equality, and either a 40‑hex `git_commit` with `source_state:'committed-export'` **or** `DALEEL_ALLOW_CANDIDATE_BUILD=true` for a null‑SHA candidate.
- Neither generated manifest exists in the staged source: `ls /app/scratch/backend/release_build.json` → No such file; `frontend/public/release.json` → No such file; `find` for release_build.json → none.
- Both are git‑ignored: `.gitignore:279 /backend/release_build.json`, `.gitignore:280 /frontend/public/release.json`.
- The generator is the app's own isolated exporter under `scripts/` (`build_release.py`, `release_source.py`, `stamp_release.py`, `verify_release_artifact.py`, `check_artifact_ready.py`, `verify_clean_release.py`). `release_source.export_local()` runs `git rev-parse` / `git archive` / `git ls-tree` — i.e. it is **git‑based**. The Emergent pipeline never invokes this exporter.
- The pipeline stages a **git‑less** copy: `/app/scratch/.git` does not exist. `pull_source` copies the preview `/app` tree (minus node_modules/.git) and the build runs `yarn install && yarn build` directly (package.json `"build": "craco build"`; build-frontend-artifacts.sh and Dockerfile.cloudbuild both just `yarn install … && yarn build`).

Net: the manifests the gate demands are gitignored artifacts produced only by a git‑based exporter that the pipeline does not run on a git‑less checkout → the file can never be present at pipeline build time → the gate always throws ENOENT. This is a **source/code** fault, not a pipeline, secret, tier, or infra fault. No pipeline/manifest change can make this file appear.
