## 2. The real "no data in all tabs" symptom IS reproduced in production logs
Root cause is a **MongoDB read-layer timeout on `product_snapshots` aggregations**, surfacing differently per endpoint:
- `GET /api/my-products?...days=30` → **503 Service Unavailable** (bounded). Trace: `my_products_cache.py:115 shared_load` → `asyncio.wait_for(operation, timeout=REQUEST_TIMEOUT_SECONDS)` → `TimeoutError: read operation timed out`; underlying `pymongo.errors.NetworkTimeout` in `price_cohort.py:170 build_cohorts` aggregate.
- `GET /api/market-share/overview?days=30&include_today=false[&comparison_mode=all]` → **500 Internal Server Error** (unbounded). Trace: `market_share.py:193 _latest_snapshots` → `db.product_snapshots.aggregate([...])` → `pymongo.errors.NetworkTimeout`; also `ERROR:price_read_limits:Price analytics read failed: price_query_timeout`.
- Common DB error on every failing path: `pymongo.errors.NetworkTimeout: customer-apps-shard-00-01.rzgpzb.mongodb.net:27017: The read operation timed out`.
- Lightweight endpoints are healthy: `GET /api/health` → 200, `GET /api/release` → 200.
This matches the prior RCA's shape (MyProducts controlled 503; MarketShare unbounded timeout surfacing here as 500).
