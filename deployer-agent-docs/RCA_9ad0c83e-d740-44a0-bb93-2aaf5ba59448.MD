## Root cause (confirmed + reproduced)
The production build invokes `release-build/prepare.cjs` → `makeReceipt()` → `apiOrigin(env)`, which does `new URL(process.env.REACT_APP_BACKEND_URL)` and throws on any value that is not a bare HTTP(S) origin — **including empty string**.

At build time `REACT_APP_BACKEND_URL` is **empty**, and that is correct/expected:
- `frontend/.env` ships `REACT_APP_BACKEND_URL=https://price-intel-dev.preview.emergentagent.com`.
- The deployment manifest `Dockerfile.cloudbuild` (`frontend-build` stage) runs:
  `RUN sed -i "s|https://[^/]*preview[^/]*\.emergentagent\.com|${BACKEND_URL}|g" /app/.env || true`
- For a **Cloudflare same-origin** frontend the `BACKEND_URL` build arg is intentionally empty, so the sed rewrites the preview URL to nothing → `.env` ends up with `REACT_APP_BACKEND_URL=` (empty).

Reproduced directly in sandbox:
```
node -e "process.env.REACT_APP_BACKEND_URL=''; require('./release-build/receipt.cjs').apiOrigin(process.env)"
→ THROW: REACT_APP_BACKEND_URL must be an explicit HTTP(S) origin
```

So: **empty/unset is a legitimate Cloudflare same-origin configuration, NOT a missing/blank secret.** `REACT_APP_BACKEND_URL` is a platform-managed SYSTEM key; nothing in the Secrets tab needs changing. The new `release-build/receipt.cjs` strict validator (added since the last successful run) does not allow the empty same-origin case, which is what breaks the build.

## Confirmation that runtime already supports empty same-origin
`frontend/src/lib/api.js` `resolveApiBase()` already handles empty/mismatched env:
- empty `REACT_APP_BACKEND_URL` → `${window.location.origin}/api`
- set but origin ≠ page origin (e.g. custom domain `daleel.hrm-sa.com`) → also falls back to `${window.location.origin}/api`
So same-origin at runtime is intended and working; only the build-time receipt validator rejects it.

## Additional source blockers to account for in the fix (observed, not just the first throw)
1. `receipt.cjs::apiOrigin` has a **second** throw after the URL parse: it rejects any origin with credentials/path/query/hash, a `pathname !== '/'`, or untrimmed whitespace (`REACT_APP_BACKEND_URL must be an origin without credentials/path/query`). A fix that permits empty/unset must branch BEFORE `new URL()` and still apply these checks when a non-empty value IS supplied (preserve strict validation of real HTTP(S) URLs).
2. `release-build/build-plugin.cjs::BuildReceiptPlugin` independently re-checks, during webpack `processAssets`, that the DefinePlugin-baked `process.env.REACT_APP_BACKEND_URL` equals `receipt.api_origin`, else throws `Compiled API origin differs from frontend build receipt`. Whatever sentinel `apiOrigin` returns for the empty case (e.g. `""`) must stay consistent with what DefinePlugin bakes, or this plugin will become the next blocker.
3. Strict path is currently INACTIVE for this build: neither `frontend/public/release.json` nor `backend/release_build.json` exist and `DALEEL_REQUIRE_VERIFIED_RELEASE_BUILD` is unset, so `prepare.cjs` runs the non-strict managed path. `apiOrigin` is still called via `makeReceipt` regardless of strict/non-strict, so the empty-origin fix is required on both paths. Keep the strict-manifest / readiness / writer safeguards unchanged.
